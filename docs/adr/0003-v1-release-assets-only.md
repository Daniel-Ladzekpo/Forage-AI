# v1 ships release-asset-only Packaging and hosted-link Shortcut Apps

Forage v1's `Package` path is limited to reusing a Candidate's published GitHub Release asset; the allow-listed recipe builds from ADR-0001 (PyInstaller, Tauri, Electron-builder, Go build) do not ship in v1, and the Shortcut Creator's `localhost-launcher` mode is likewise deferred — both execute third-party build tooling on the user's real machine, the exact risk class ADR-0001 was written to contain, and deferring them keeps every "run untrusted code" path behind a single v1.1 milestone that also settles the build-sandboxing question (Windows Sandbox requires Pro/Enterprise/Education and is unavailable on Windows Home, likely half the target audience). Candidates with no usable Windows Release asset are refused by the Risk Card with a reason and offered a `hosted-link` Shortcut App as the universal fallback, so v1 only ever downloads maintainer-published assets or opens URLs. This narrows v1 scope without contradicting ADR-0001, which constrains how `Package` may happen, not which paths must exist on day one; it partially defers spec user story 6 (build from source via vetted recipes) to the v1.1 "run third-party code" milestone, together with the recipe engine, `localhost-launcher`, and sandboxing decision.

Status: accepted
